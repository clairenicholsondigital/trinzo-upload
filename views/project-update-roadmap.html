Project update roadmap

A lightweight product and engineering roadmap for the Project Update workflow. The aim is to keep future work visible while focusing on the improvements that will make the biggest difference to day-to-day use.

Current foundation

Reliable project understanding

  • Deterministic project selection.
  • Project context, milestones, project health overview and risk lineage.
  • Official project snapshots.
  • Context-aware trend analysis across previous reports.

Project knowledge

  • Manual and background knowledge.
  • Approved report ingestion.
  • MiniLM semantic search.
  • Hybrid semantic and keyword retrieval.
  • Knowledge queue and backfill tooling.

Report generation

  • Retrieved knowledge supplied as supporting context, never treated as evidence from the current meeting.
  • Semantic milestone and risk matching.
  • Grounded report generation with graceful fallback behaviour.

Ask project memory

  • Project-specific Ask interface.
  • Retrieval-only fallback when generation is unavailable.
  • Scoped retrieval across approved project knowledge.

Next priorities

Evaluation and quality

Build a repeatable evaluation suite so quality can be measured consistently rather than relying on individual examples.

Examples include:

  • First meeting with no previous context.
  • Existing project with extensive history.
  • Duplicate transcript handling.
  • Background document retrieval.
  • Graceful degradation when services are unavailable.

Meeting minutes workflow

Complete the end-to-end workflow for generated meeting minutes.

Potential improvements include:

  • Saving generated Word meeting minutes directly to the project workspace.
  • Reviewing whether SharePoint should reference the stored document rather than generating a fresh export each time.
  • Consistent PDF and Word outputs from the same underlying meeting minutes.
  • Reusable meeting minute templates.

User experience

Refine the experience around longer-running AI tasks.

Areas to improve include:

  • Clear progress feedback while processing.
  • Target processing time for typical meetings.
  • Better handling of large meetings.
  • Clearer success and error messaging.

Output quality

Continue improving the usefulness of generated reports rather than simply increasing detail.

Areas of focus:

  • Appropriate level of detail for different meeting types.
  • Better prioritisation of important discussion points.
  • More consistent action extraction.
  • Stronger distinction between decisions, discussion and future actions.
  • Reduced repetition.

Documentation

Document the operational aspects of the system.

  • Embedding worker behaviour.
  • Queue monitoring.
  • Ask endpoint modes.
  • Dependency notes.
  • Backfill guidance.

Future

Generated Ask validation

Validate generated responses using disposable test knowledge before using real project data for external model evaluation.

Knowledge lifecycle

Not currently required.

If project memory grows significantly, consider:

  • Keeping the most recent approved reports readily searchable.
  • Summarising older reports into historical knowledge.
  • Never automatically archiving official or manually curated knowledge.
