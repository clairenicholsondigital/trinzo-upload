# Contact-for-review duplicate comparisons

## Scope

An opt-in nomination class for generated actions arranging a review through a named contact. It recognises bounded `Follow up with <person> to review <material>` and `Follow up with <person> and obtain/get/request a review of <material>` instructions. This does not merge by opening words, recipient or shared citations alone.

The motivating root cause was two independent discovery passes creating paraphrases that final semantic reconciliation never nominated. Earlier mechanical checks correctly could not prove full retention, so both rows survived. The fix admits this narrow class to the existing independently reviewed comparison path.

## Admission and preservation

- `MEETING_MINUTES_AGENT_CONTACT_REVIEW_V1=1` is captured as `contactReviews` in the immutable semantic policy. Missing/old snapshots retain previous nomination behaviour. Rollback disables new nominations without invalidating existing receipts/recovery.
- Same accountable owner, same named contact, matching bounded object vocabulary and shared source evidence are nomination requirements. Existing qualified contact-paraphrase comparisons retain priority. The shared one-contact and total pair/time budgets are unchanged.
- Source proposal and independent challenge must both establish supported commitments, the same review arrangement/referent/occurrence, and full retention in one unchanged existing survivor. The accountable arranger is distinguished from the review performer. Separate reviews, execution or stronger unsupported outcomes are vetoes, not retry opportunities.
- Reviewer-authored/kept records, warnings, dates, dependencies, rejected timing history, quantities, compound work, alternatives and unfamiliar metadata remain excluded.
- Full source/owner/retention validation, final survival checks, evidence limits and validated original-record receipts remain required. No new rewriting or warning resolution occurs.

## Qualification

Two isolated Microsoft assessments of the saved Eakin register (including one with current occurrence IDs) each reduced 11 actions to 10, retaining one unchanged contact-for-review action. A generic real-service control containing two separately assigned reviews retained both rows after the first source review. Five frozen drafts nominate only this new pair; feature-off packets match the previous implementation exactly. Save/payload/recovery checks retain both originals, all warnings and unrelated actions. No library drafts are modified by qualification.

## Remaining work

The compilation pair is deliberately outside this class: one row contains an unresolved dependency and warnings, while the other retains an explicit quantity. Neither unchanged row demonstrably retains all details. It needs separate work-identity, metadata-preservation and independently verified rewrite qualification. This release does not close general semantic action duplication or reduce review-card counts.
