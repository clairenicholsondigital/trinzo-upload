# AI-011: one list described as preparation and provision

## Problem and correction

The frozen 27 October DITA output contains two same-owner actions asking for one shipping-country list for language assessment. Both cite exactly the same two source turns. One starts “Prepare” and the other “Provide”. Existing bounded-survivor nomination requires the same opening operation, so neither Microsoft verification nor final proof could consider the pair. PR #180's earlier same-operation correction remains valid; this generated variant is outside that class.

The contained-requirement comparison now has a separate generic `list_deliverable` shape. It nominates one `prepare a/the/one list of … for …` row against one `provide …` row, choosing the unchanged provide-list row for independent review. The objects must share their first two informative tokens, purposes must match, and the owner and complete source-reference sets must be identical. This is a nomination, not proof that preparation and provision are interchangeable.

Existing eligibility excludes timed, flagged, reviewer-authored, unowned, multiply-owned, rejected-date and qualified instructions. Both source reviews must establish supported commitments to the same list, scope, purpose and occurrence, plus complete retention in the unchanged survivor. Explicitly separate preparation or delivery, uncertainty or a failed challenge retains both rows. A semantic veto is not retried. Only a validated list certificate can discharge the operation difference; other conflicts remain active. Existing pair/cost limits, final-preservation checks, receipt validation and exact recovery apply.
