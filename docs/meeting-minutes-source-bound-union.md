# Source-bound review workflow and repeated-process editing

Scope: `/meeting-minutes-agent` generation and its owned save/publication boundaries. No transcript names, quotations, document vocabulary or identifiers are production matching rules. Existing library drafts are not rewritten by deployment.

## Action workflow fix

Independent discovery responses use local IDs. Matching IDs do not establish the same task. Distinct review/document workflow instructions now survive that boundary intact, including a reproduction where the older containment shortcut incorrectly preferred an instruction missing an operation.

A separately gated editor may combine **one** narrowly eligible pair after generation. Both must be generated, unflagged, untimed, single-owner review/document workflows with substantial shared citations and wording. Reviewer content, protected occurrences, conditional or alternative work, timing rejection history, conflicting recipients, destinations and scope stay outside this class.

The four bounded requests inventory every original claim, propose one instruction, independently verify every original/output claim, then independently challenge whether this is one explicitly assigned outstanding work event. Every request uses the existing Microsoft endpoint, one attempt, with a shared 120-second budget. The editor preserves all operations, responsibility and scope; unsupported originals or any uncertainty retain both rows. The model cannot introduce new content vocabulary, protocol instructions, alternatives, conditions or slash alternatives even if every model check approves them.

Receipts bind exact full originals, final wording/metadata, normalized source, meeting date and the generation identity allocation. Unchanged owned saves preserve the server proof; client-provided proof is ignored. Changed source/date/wording invalidates permission to suppress originals. All originals and responses remain privately recoverable. Proofs are excluded from the public draft response.

Enable: `MEETING_MINUTES_AGENT_WORKFLOW_UNION_V1=1`. Default is off. Rollback is setting this flag to `0` in all three minutes processes. Disabling future editing does not delete previously stored originals or receipts.

## Discussion fix

Non-calendar Discussion normalization retains up to twelve valid supplied references instead of arbitrarily keeping only the first eight. Actions, default evidence resolution and date-specific evidence selection retain their old policies. This does not permit the discovery adapter to accept unverified citations outside its anchor.

A separately gated nomination compares at most one adjacent pair of generated, unflagged main paragraphs under the same unprotected topic, even when their citations are disjoint. It requires strong lexical/semantic similarity and bounded source locality. Similarity only nominates: it never authorizes a deletion. Future/event wording, manual content, warnings, supporting children, ambiguous identities and excessive context remain excluded.

The cross-mention class supplies the complete local exchange (at most forty units, 48k characters, 12k per unit); the existing partial-overlap class keeps its twenty-four-unit bound. Up to twenty-four original citations may be archived in a candidate; the final paragraph still must fit **all** independently verified witnesses within twelve citations. No verifier witnesses are pruned to force acceptance. Every original reference remains in restoration history.

Independent verification must affirm one operating process, consolidated shared facts, distinct events kept separate, every original claim retained and every output claim supported. Source-supported vocabulary, attribution, numbers, names and qualifications remain vetoes. Equivalent ordinal party-role spelling is recognized without permitting a change of role or quantity.

Enable: `MEETING_MINUTES_AGENT_DISCUSSION_CROSS_MENTION_V1=1` alongside the existing bounded-rewrite flag. Default is off. Setting the new flag to `0` restores the earlier nomination scope. Other semantic/deduplication features are unchanged.

## Validation and limits

- New deterministic tests cover positive rewrites, incomplete/unsupported inventories, lost operations, owner/recipient/date/source changes, separate events, provider failures, independent discovery ID collisions, manual/flagged records, metadata overflow, exact restoration, generation admission, owned saves and public proof redaction.
- Real Microsoft validation on the saved Eakin pair produced one source-verified instruction retaining review, documentation and update, and both probability and frequency scope. Admission, JSON persistence, public serialization and Word export preserve it.
- Two unsafe real proposals (editing-protocol language and changing mandatory work to alternatives) were rejected by additional deterministic vetoes. They were not treated as successful validation or silently accepted on model approval alone.
- The private DITA benchmark has a verified two-to-one rewrite, replayed through the final validators with exact restoration and Word export. Character count changed only from 549 to 548: this demonstrates a bounded entry reduction, **not** a substantial prose improvement. A subsequent real attempt dropped attribution and was correctly rejected. Variability and remaining conservative refusals are open limitations.
- The three repeated DITA main paragraphs are from the private benchmark, not the currently saved library draft. No claim is made that existing live drafts visibly changed.
- Five saved-output offline failure controls retain all originals. These are not a new five-transcript generation run.
- The relevant Node suite passed 2,888 tests (two skipped); all 426 Python checks and the bundle build passed. Evidence is recorded in the private release directory. The two existing UI-state/layout failures reproduce on the deployed baseline and remain open; assertions and meaningful coverage were not removed.

Wider repetition, more distant/non-adjacent process mentions, warning-bearing content, conditional/dated action unions, unsupported or missing information, and better process paraphrasing remain outside this bounded release. Fresh generation is still needed to measure aggregate reviewer burden.
