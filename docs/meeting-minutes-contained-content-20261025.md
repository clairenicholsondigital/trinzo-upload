# Source-proved contained action content

## Scope

An optional generation-only class can remove a content/detail instruction when
one existing instruction already explicitly contains it within the same named
deliverable. It never rewrites the surviving instruction. This does not close
semantic duplication generally, and does not cover dependency-qualified work.

`MEETING_MINUTES_AGENT_CONTAINED_REQUIREMENTS_V1=1` opts new runs in. The captured
policy is frozen; legacy/in-progress work without it does not adopt the class.
It is action-only. Existing contact and bounded-survivor classes retain priority
within the existing two-pair budget; at most one contained-content pair is checked.
The dedicated contained-content scope has a one-pair budget.

## Admission and preservation

Both rows must be generated, unflagged, untimed, single-sentence instructions
with the same single owner and no unknown record metadata or rejected/unresolved
timing. The fuller instruction must explicitly create a named container and
include its content. The other must explicitly describe/include content in that
same container, with all required content tokens already present. Multiple
possible parent instructions, independent operations, conditional wording and
unsupported date shapes stay outside the class. Shared citations only nominate
a comparison and never prove equivalence.

For each nominated pair, two separate Microsoft requests inspect immutable
originals and bounded source context. The second is an independent challenge and
receives no earlier answer. Both independently assess source support for BOTH
originals, retention of the discarded original, and its role as required content
of the selected existing survivor. An inline month requires an explicit
content-effective-time assessment. A structural failure or semantic veto retains
the rows; semantic vetoes are not retried.

Only a certificate binding both reviews, both complete originals, full source
snapshot, supplied context and exact expected final survivor can exempt three
specific generic conflicts: operation, parsed destination, and inline temporal
occurrence. Every other owner/recipient/condition/quantity/qualification guard
remains active. Whole-clause mappings and source spans are regenerated and
compared exactly. The evidence union must fit the existing eight-source limit;
removed, ambiguous or missing source references cannot authorize a merge.

Provider transport strips supplied certificates. Certificates are attached by
the server after independent reviews. Existing receipts archive complete
originals and are revalidated during final preservation and identity admission.
Reviewer text/evidence edits invalidate them. The existing Restore separate
actions control uses the same receipt checks and retains reversible history.
An optional-class failure cannot roll back an independently successful existing
class; existing legacy-stage failure behavior is unchanged.

## Qualification

Private isolated qualification used nine actual calls to the existing Microsoft
endpoint, with no Trooper calls or library writes:

- Allotment: the fuller renewal-letter instruction survived both source checks
  in both input orders. The repeated content requirement was removed and receipts
  remained valid after identity admission.
- Two unseen generic content examples: both independent reviews passed and the
  intended existing instructions survived admission.
- A withdrawn-assignment control was vetoed, without retrying for approval.
- Eakin's dependency-qualified pair was not nominated and used no provider call.

The first Allotment attempt made zero calls because nomination split a content
phrase at an internal preposition. The generic parser was corrected to recognize
the final container phrase, then both input orders were checked. No negative
semantic verdict was changed or retried.

Regression coverage includes disabled/legacy policy, both input orders, ambiguous
parents, independent work, owner/qualification/warning/reviewer exclusions,
content timing veto, independent request binding, tampering with exact mappings
and source quotes, untrusted certificate stripping, capacity, removed evidence,
legacy-success/new-failure isolation, final preservation, identity admission,
JSON reload, background save, public redaction, Word and PDF exports, and the
owned restore endpoint.

Private evidence is retained outside Git in
`/root/trinzo-contained-content-qualification-20261025`. Library snapshots prove
all 59 drafts and environment settings were unchanged by qualification.

## Limits and next steps

This is a conservative class, not an instruction to trust similarity. The same-
dependency paraphrase false veto, Eakin dependency/IT qualifications, separately
trackable work, and more general discussion repetition remain open. Do not widen
the three conflict exceptions, approve vetoes by retrying, or merge the held global
research prototype to address those cases. Assess any future fresh-generation
outputs before counting broader reviewer-burden improvements as fixed.
