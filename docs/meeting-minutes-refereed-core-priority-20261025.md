# Preserve explicit core priority

The latest saved processing trace shows a core-classified version-traceability
record grouped with a longer supporting paragraph. Compaction selected by length,
not the settled core verdict. The core record became supporting text; later
subject rehoming could not place its distinct version information and filed it.
The record's discovery hint still said supporting even after the referee voted
core, so that hint cannot establish current authority.

`MEETING_MINUTES_AGENT_REFEREED_CORE_PRIORITY_V1` separately captures the policy.
Only uniquely identified settled core targets supplied by the agent receive
priority within the existing same-type, client-ready compaction group. A discovery
hint, generated label, topic, similarity or source overlap cannot confer it.
Distinct numerical values across two authoritative core rows prevent grouping and
are preserved through the next normalisation boundary. Default shared-helper and
legacy run behaviour stays unchanged. Source grounding, raw-speech rejection,
fidelity checks, task-only filtering, warnings and publication safeguards remain.

This restores the main position of eligible already-classified material; it does
not promote the entire filing pool. Unassessed supporting material, pure tasks,
mixed records requiring a rewrite and uncertain source bindings remain separate
review work. No wording is synthesized or split by this patch.
