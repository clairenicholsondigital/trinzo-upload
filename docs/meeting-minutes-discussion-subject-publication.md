# Subject assessment and publication accounting

These changes apply to `/meeting-minutes-agent` discussion generation. They do
not change action extraction, Microsoft configuration, the candidate budget,
publication safeguards or existing saved drafts.

## Selection

The previous round robin grouped named technical subjects by broad editorial
facets. A clock issue could become overflow under a frequency-justification
representative simply because both mentioned risk. Untitled transcript windows
also occupied several facet groups, contrary to the intended single source group.

The selector now reserves one independent candidate for each readable named
primary/recovery subject, within the existing budget. Remaining slots use the
balanced facet selection. Readable primary/recovery statements rank ahead of
secondary extractor summaries and raw windows. Secondary headings do not each
reserve a slot: isolated validation showed that doing so could displace qualified
primary claims with more assertive secondary summaries.

Paraphrase clustering requires a positive subject match in addition to the
existing lexical, citation and quantity checks. Distinct overflow is not attached
to an arbitrary representative. All ledger identities are accounted as supplied,
clustered or unassessed. Readable unassessed editorial material uses the existing
positive subject-placement or lossless filing path without an inherited target
or invented referee verdict. Existing downstream evidence/editorial checks and
detail promotions still apply.

Legacy overflow metadata also releases context without an inherited target and
cannot be consumed as settled by partial fallback. Reviewer protections and
separately unresolved supplied members keep their existing handling.

## Accepted core targets

When multiple candidates are explicitly accepted for the same target, rebuilding
that target prefers an approved readable candidate over raw speech. A supporting
or rejected candidate cannot supply that replacement. No new prose is generated.

New private publication accounting checks accepted target identities after
compaction, after the final editor and again after generation cleanup/semantic
reconciliation. Primary IDs and recorded predecessor aliases establish survival;
similar prose alone does not. Discovery-record aliases require the exact claim.
Uncited or ambiguous primary matches do not certify publication. Retained context,
Needs filing, withheld and unmaterialized targets are distinguished from visible
targets. Nested context is included.

A fully answered referee response can remain authoritative for its candidate
decisions while publication remains incomplete. Sufficiency can no longer report
success just because reconstruction created an ID that later disappeared.
There is no blanket discovery fallback, forced publication or reopening of valid
supporting/reject decisions to make that status green.

## Tests and validation

Generic fixtures cover distinct subjects sharing risk vocabulary, raw-window
budget pressure, primary qualifications versus numerous secondary headings,
unassessed overflow including legacy contracts, approved-only reconstruction,
aliases, nested retained content, uncited/ambiguous IDs and final cleanup.

The prior overflow test now checks complete source accounting through explicit
unassessed IDs rather than requiring unrelated inherited routes. The partial
fallback fixture keeps its independently supplied candidates in distinct named
subjects. An older delivery test is aligned with the already-deployed timing
guard: compatible rows still bundle, while a separate condition and timing stay
intact. That original assertion fails on the deployed baseline; no action code
was changed to satisfy it.

Offline comparisons cover both archived five-transcript sets. Isolated checks
reuse saved discovery with fresh Microsoft referee/quality checks, prohibit
database access and other provider endpoints, and suppress action prewarming in
the harness only. Library drafts are preserved. These are discussion-only checks,
not five new library drafts or full action/summary runs.

## Remaining limits

This fixes bounded input starvation, arbitrary overflow inheritance and false
publication-success accounting. It does not prove every subject belongs in the
main minutes. Microsoft can still classify material progress as context, choose
an inappropriate existing target, or accept raw fragments which the publication
gate correctly refuses. Those outcomes remain visible in private diagnostics;
the app does not bypass safeguards to conceal them. Semantic repetition and
source qualification still require their existing checks and further targeted
work where failures are demonstrated.
