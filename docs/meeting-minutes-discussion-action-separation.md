# Source-verified discussion/action separation

The discussion extractor/referee can retain a whole record for its requirement,
current fact or unresolved question while also retaining an embedded assignment.
The existing literal action deduper cannot safely remove that clause or equate
an indirect contact recap with a differently worded action. It stays unchanged.

This separate bounded editor runs after the accepted Actions register is final.
It inventories every assertion, distinguishes substantive discussion from the
communication operation, proposes a shorter discussion record, then independently
verifies source truth, complete retention and warning scope. An information gap
must retain whose understanding is incomplete; it cannot become a globally
unknown fact or an answered question. A question is stored as an open question
with explicit question wording, rather than relying on discovery's label alone.
It never deletes a whole record or moves distinct information to Needs filing.

Only recognised generated records/actions are eligible. Reviewer trees, unknown
metadata, ambiguous identities/sources, missing owners, action warnings and
non-attribution warnings on the edited discussion record are excluded. Generated
supporting trees stay byte-exact. An attribution warning must identify an original
name; that name/relationship must remain in the revised record, with the exact
warning unresolved on the same identity. The verifier must explicitly confirm
that it still applies. Other warning classes remain protected.

The comparison includes the recorded source passages with two neighbouring turns
and, where available, one strong task-subject/person recap witness with its
neighbours. General person/topic overlap cannot retrieve a witness. The entire
packet must fit 24 source units / 48 KB; overflowing packets are retained, not
truncated. Retrieved context is not automatically a published citation or date.
Only independently verified witnesses can expand citations, with a 12-reference
limit and no silent truncation.

## Necessary paired action correction

Real-data testing found that an existing action can misstate clarification as
'review'. Such an action cannot justify deleting the information-seeking work.
The editor may therefore propose one existing communication action's wording
correction, only alongside a retained discussion question. It cannot change its
ID, owner, recipient, timing or conditions, add work or fix a different task.
This first version excludes corrections to actions with stated structured timing.

Every original action assertion must be inventoried. The independent verifier
must establish that retained assertions were source-supported and remain intact;
a corrected assertion must have been unsupported in the original and be faithfully
corrected from source. The complete revised action must be source-supported, the
same work, the same roles, and contain no additional work. This is an explicit
source-fidelity correction, not permission to hide a failed discussion check.
All original action metadata and wording remain in the recovery archive.

## Bounds and failure handling

At most one pair is nominated per draft. There is one proposal and independent
verification, with at most one repair for invalid output or failed coverage.
The failed proposal/checks are retained privately. An identical vetoed proposal
cannot simply sample the verifier again. Every repair passes all the same checks.
Provider failure, malformed/nonliteral quotations, missing assertions, uncertain
coverage, changed inputs or failed warning checks preserve the original pair.
The maximum is four optional calls, each bounded to 45 seconds; many drafts have
no candidate and make no calls.

The stage runs only under the existing bounded-discussion-editor gate. Set
`MEETING_MINUTES_AGENT_DISCUSSION_ACTION_SEPARATION_V1=0` to disable it separately.
It does not enable broad semantic reconciliation, edit other pages, change the
Microsoft active configuration or refresh existing library drafts.

The summary temporal comparator is used only when a real temporal proposition is
present. In a local comparison copy, 'clarification on when ...' is an information
question; a bare 'when ...' prerequisite, dates, durations and original conditions
remain protected. Source/meaning verification still applies to every assertion.
No global timing rule or old merge guard is relaxed.

## Persistence and restoration

The existing private discussion recovery chain retains earlier consolidation
originals. The pair additionally stores before/after action bindings. Only one active pair is permitted per draft. Background Actions publication saves the paired Discussion proof atomically, and binds allocated action identities only when all content matches exactly. Concurrent source/date/Discussion edits defer the entire pair; reviewer-owned Actions defer it to proposals without applying the Discussion change. Unchanged
owned saves preserve exact verified discussion and corrected-action citations;
client-supplied proof cannot authorise that exception. A changed/removed covering
action restores only the unedited separation topic, retaining earlier wins and
reviewer edits. Source changes invalidate recovery.

For a paired correction, the existing restore control explicitly says 'Restore
original discussion and action wording'. It restores both originals only while
the corresponding generated content is unchanged; reviewer changes are never
overwritten. Owned save/reopen, restore, undo/redo and Word/PDF paths are tested.

## Validation and remaining scope

Tests use generic fixtures and negative controls for different work/roles,
quantities/conditions/timing, source support, warning mapping, reviewer edits,
unknown metadata, malformed replies, provider failure and restoration. Real
private comparisons use all five saved outputs and retain all rejected attempts.
The Eakin clarification case requires a paired source-intent correction; Abbott's
training-pack action does not cover the separate product overview and is retained.

A fixed-source experiment also tests upstream atomisation instructions. Those
instructions are not included in production: the experiment introduced a decision
classification error and retained task recaps/extra repetition. A prompt-only
change is not established as safe by those results.

This is a bounded defect-class improvement, not proof that all mixed paragraphs
across arbitrary transcripts can be edited safely. Flagged fidelity/meaning cases,
missing accepted actions, distinct purposes and ambiguous source references remain
available for review. Fresh full-workflow comparisons and the release evidence
report distinguish validated edits from retained cases and broader open work.

The release validation replay accepts a source-verified Eakin clarification pair
and leaves the other four saved drafts unchanged, including their filing counts.
The final stricter independent verification accepted one of two distinct frozen
proposals and vetoed the other; vetoes are retained rather than resampled away.
This establishes a safe accepted case, not guaranteed model consistency.

Five additional fresh private workflows completed using the existing Microsoft
Actions fallback after optional secondary extraction timed out. Their protected
meaning/timing cases yielded no eligible edits under the final guards. They do
not establish a broad improvement in fresh-run task mixing, nor validate the
normal secondary Actions extractor. The library, live cache and Microsoft
configuration were untouched. Further expansion needs reliable action coverage
and warning-safe evidence, not weaker placement safeguards.
