# Connected action evidence preservation

Scope: Meeting Minutes Agent action normalization and its existing commitment-evidence backfill. Production call-site review found these action paths in the agent routes; the reviewed-AI-edit helper imports the same module for Discussion only. No other page or Microsoft configuration is changed.

The normalizer could replace a supplied assignment/acceptance/tool-dependency exchange with stronger noun matches, then append a nearby owner's different or already completed task as the commitment anchor. This weakens later source verification even when the original model supplied relevant citations.

This change preserves a bounded, already supplied exchange when its work description is connected to a named assignment or the exact owner's ongoing commitment. The owner cue must be within two source rows of the relevant supplied turn. First-name assignment references must be unambiguous among source identities. Topic changes break the connection; unrelated timing-only answers remain excluded. The existing eight-source cap is unchanged, with required field sources before retrieval context. Packets exceeding the bounded input limit take the existing path.

Keeping a supplied passage is provenance, not a semantic or ownership approval. Existing wrong-citation remapping, owner validation, timing rejection, qualifier checks, duplicate guards and review flags remain active. No tasks are merged by this change.

The additive owner-anchor lookup now requires current work by the resolved exact source identity and a matching task object. A generic operation such as prepare/review does not establish that an annual finance report is the same job as an annual safety report. A completed added/drafted passage is not borrowed as the commitment for remaining work. A mixed passage containing such completed material is conservatively excluded from this additive lookup; it may still be retained when supplied through the ordinary evidence path.

A legitimate later anaphoric promise such as a review acceptance remains recoverable when the intervening substantive discussion continues naming the same work. A topic change or different substantive subject closes that link.

Reviewer saves and reviewer-authored action records retain their valid supplied references rather than silently repeating source allocation. Existing support/owner warnings may still flag an unsupported choice. This preserves the reviewer decision without treating it as verified source truth.

## Qualification

Generic behavior tests cover assignment/acceptance preservation, dependency context, completed work, different tasks by the same owner, mixed completed/future turns, anaphoric topic changes, ambiguous first names, real commitments containing questions, wrong-citation repair, subsequent-topic timing and reviewer saves.

Private replay of four captured primary actions demonstrates:

- Both renewal-letter actions retain their assignment/acceptance references plus the fee context; the separate waiting-list promise is not appended.
- Both driver-generation actions retain tool-access/generation evidence, recover the supplied dependency wording and exclude the completed-language turn as an added commitment anchor.
- Action wording, owners and task counts remain unchanged. Duplicate deletion is deliberately not claimed.
- Final backfill, generated identity admission, JSON round-trip, reviewer-save normalization, public proof redaction and Word export preserve the correction. No provider calls or library writes are needed for these replays.

## Limits

This is not a universal citation entailment checker. It does not automatically merge different verbs, decide ambiguous intent, solve grouped-evidence materialization or implement the proposed canonical action register. Those remain separately qualified work. Existing library rows are preserved; generation and subsequent explicit reviewer operations use the new code.

Release gates: relevant Node regressions, the complete browser UI suite, Python regressions, bundle build, captured-data qualification, exact tested/merged tree, preserved library/environment/cache/runtime settings and authenticated-route smoke responses. No runtime feature flags are added or changed.
